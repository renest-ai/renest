# Escape hatch versions

`restore.sh` is the escape hatch: a single shell script that rebuilds a nest
using only curl, jq, sha256sum, tar and uv. From nest format 2.3 on, a copy of
it travels inside every nest at `.renest/escape/restore.sh`.

**That copy is frozen.** It is exactly the script as it stood on the day the
nest was packed, and fixes made afterwards never reach it. The script carries
no version field; the only marker is the comment at the top of the file. This
page is the other half of that: look your copy up by its hash.

## Which copy am I holding?

```
sha256sum .renest/escape/restore.sh
```

Find that hash in the table below. If it is not there, it is not one of ours.

Two layers, honestly:

- **The copy in your nest is the floor.** It will get your bytes back even if
  we no longer exist. That is the whole point of it.
- **The latest copy from us is better.** Bugs listed here are fixed in it, and
  it reads every format from 2.0 up.

Use the latest one when you can reach us. And note: someone else's nest carries
someone else's copy of this script. Running it is running their code on your
machine -- use your own copy, or check its hash here first.

## Recorded issues

An empty cell in the table's issues column means nothing was recorded against
that version, not that it was free of problems. Only what we found and fixed
is listed.

| Issue | Fixed on | What was wrong |
| --- | --- | --- |
| `no-transfer-speed-floor` | 2026-07-25 | A stalled download was never given up on, so the script could hang indefinitely instead of failing. |
| `stale-failure-record` | 2026-07-26 | A leftover failure record from an earlier run made a fully successful run report itself as failed. |
| `git-https-source-refused` | 2026-08-12 | Dependency sources of the form git+https:// were judged untrusted and refused, so nests using several of the most common extensions could not be rebuilt. |
| `nest-own-code-treated-as-remote` | 2026-08-12 | Code carried inside the nest itself was treated as an outside server, so fine-tuning nests could not be rebuilt at all. |
| `missing-library-notice-buried` | 2026-08-12 | On a machine short of a system library, the closing line saying so was covered up by the Done line above it. |
| `no-libc-check` | 2026-08-20 | The C library version was not checked, so a nest packed on a newer system passed every byte check on an older one and then crashed on first start. |
| `presigned-urls-printed` | 2026-08-20 | Presigned download links were printed in full in the script's own output, including on the success path. |
| `failure-output-scrolls-away` | 2026-08-21 | When a rebuild failed, the output explaining why only flashed past the screen instead of being kept. |
| `silent-on-cpu-shortfall` | 2026-08-22 | Said nothing when the machine's processor lacked instructions the environment needs. |
| `silent-on-chip-family-change` | 2026-08-22 | Said nothing when the target machine was a different processor family than the one the nest was packed on; the failure surfaced only after the whole download. |
| `three-hard-edges` | 2026-08-22 | Three defects at once: wrong bytes were left in place instead of being removed, a failed install command was not reported, and a material file whose name contains a space produced a wrong error. |
| `no-word-on-your-own-material` | 2026-08-22 | After a rebuild it never said which of your own material files you have to put back yourself. |
| `false-alarms-off-linux` | 2026-08-23 | On machines that are not Linux it raised a string of alarms that did not apply. |
